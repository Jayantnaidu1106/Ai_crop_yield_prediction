# SIH2 - Crop Yield Prediction System

A comprehensive full-stack application for predicting crop yield based on agricultural parameters using machine learning, with Twilio OTP authentication.

## 🌟 Overview

This project consists of three main components:
1. **Backend (Node.js + Express)** - Authentication API with Twilio OTP verification
2. **Frontend (React + Vite)** - Modern web interface with Tailwind CSS
3. **ML API (Python + FastAPI)** - Crop yield prediction using Random Forest model

The system uses a trained Random Forest model to predict crop yield (tonnes per hectare) based on various agricultural factors including crop type, season, location, area, production, rainfall, fertilizer usage, pesticide usage, and temperature.

## 🔌 API Endpoints

### Authentication API (Backend - Port 3000)

#### 1. Status Check
- **URL**: `GET /api/status`
- **Description**: Check if backend is running

#### 2. Send OTP
- **URL**: `POST /api/auth/send-otp`
- **Description**: Send OTP to phone number via Twilio
- **Request Body**:
```json
{
  "phoneNumber": "+1234567890"
}
```

#### 3. Verify OTP
- **URL**: `POST /api/auth/verify-otp`
- **Description**: Verify OTP and receive JWT token
- **Request Body**:
```json
{
  "phoneNumber": "+1234567890",
  "code": "123456"
}
```

### ML Prediction API (Python - Port 8000)

#### 1. Root Endpoint
- **URL**: `GET /`
- **Description**: Basic API information and status

#### 2. Health Check
- **URL**: `GET /health`
- **Description**: Check API health and model status

#### 3. Single Prediction
- **URL**: `POST /predict`
- **Description**: Predict yield for a single set of parameters

**Request Body Example**:
```json
{
  "crop": "rice",
  "crop_year": 2020,
  "season": "autumn",
  "state": "odisha",
  "area": 30000.0,
  "production": 25000.0,
  "annual_rainfall": 1200.0,
  "fertilizer": 3000000.0,
  "pesticide": 12000.0,
  "temperature": 24.5
}
```

**Response Example**:
```json
{
  "predicted_yield": 0.833333,
  "input_yield_ratio": 0.833333,
  "model_confidence": "High",
  "message": "Prediction completed successfully"
}
```

### 4. Batch Prediction
- **URL**: `POST /batch-predict`
- **Description**: Process multiple predictions (max 100 per request)

### 5. Model Information
- **URL**: `GET /model-info`
- **Description**: Get information about the loaded model

## Input Parameters

| Parameter | Type | Description | Range/Options |
|-----------|------|-------------|---------------|
| crop | string | Crop type | See supported crops list |
| crop_year | integer | Year of cultivation | 1990-2030 |
| season | string | Growing season | autumn, kharif, rabi, summer, whole year, winter |
| state | string | State name | odisha (more can be added) |
| area | float | Area in hectares | > 0 |
| production | float | Production in tonnes | > 0 |
| annual_rainfall | float | Annual rainfall in mm | ≥ 0 |
| fertilizer | float | Fertilizer usage | ≥ 0 |
| pesticide | float | Pesticide usage | ≥ 0 |
| temperature | float | Average temperature in Celsius | Any |

## Response Fields

| Field | Type | Description |
|-------|------|-------------|
| predicted_yield | float | Predicted yield in tonnes per hectare |
| input_yield_ratio | float | Input production/area ratio for comparison |
| model_confidence | string | Model confidence: "High", "Medium", or "Low" |
| message | string | Success message |

## Error Handling

The API returns appropriate HTTP status codes:
- `200`: Success
- `400`: Bad Request (invalid input)
- `422`: Validation Error
- `500`: Internal Server Error
- `503`: Service Unavailable (model not loaded)

## 🔒 Security

### Environment Variables
- ✅ `.env` files are automatically excluded from version control
- ✅ Never commit sensitive credentials
- ✅ Use strong, random JWT secrets in production
- ✅ Rotate Twilio credentials regularly

### Best Practices
1. **Change default JWT_SECRET** - Use a strong random string
2. **Use HTTPS in production** - Never send credentials over HTTP
3. **Implement rate limiting** - Prevent abuse of OTP endpoints
4. **Validate all inputs** - Backend includes validation middleware
5. **Monitor Twilio usage** - Set up alerts for unusual activity

## 🐛 Troubleshooting

### Backend Issues

**Backend won't start**
- Run `npm install` in Backend directory
- Verify `.env` file exists with all required variables
- Check if port 3000 is already in use

**Twilio OTP not working**
- Verify credentials at https://console.twilio.com/
- Check if phone number is verified (for trial accounts)
- Ensure no extra spaces in `.env` values
- Review Twilio console logs for errors

### Frontend Issues

**Frontend won't start**
- Run `npm install` in Frontend directory
- Check if port 5173 is already in use
- Clear npm cache: `npm cache clean --force`

**CORS errors**
- Verify Backend is running on port 3000
- Check CORS configuration in `Backend/app.js`

### Python ML API Issues

**Model not loaded error**
- Ensure `crop_yield_model.pkl` and `scaler.pkl` exist
- Run the Jupyter notebook to generate model files

**Connection refused**
- Check if the server is running on the correct port
- Verify no firewall is blocking the connection

**Validation errors**
- Check input parameter names and types
- Ensure all required fields are provided
- Verify crop/season/state names are in the supported list

**Performance issues**
- Consider using background tasks for large batch predictions
- Monitor memory usage with large models
- Use appropriate hardware for model inference

### General Issues

**Port already in use**
```bash
# Windows
netstat -ano | findstr :3000
taskkill /PID <PID> /F

# Linux/Mac
lsof -i :3000
kill -9 <PID>
```

**npm install fails**
- Clear npm cache: `npm cache clean --force`
- Delete `node_modules` and reinstall
- Check Node.js version (must be v20.19.0+ or v22.12.0+)

**Python package installation fails**
- Upgrade pip: `python -m pip install --upgrade pip`
- Install packages individually to identify issues
- Check Python version (must be 3.8+)
